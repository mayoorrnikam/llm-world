# AGENTS.md — rules for any agent working on LLM World

For Hermes, OpenClaw, Claude Code, Codex or any other agent. CLAUDE.md holds
the full architecture and the reasons; this file is the part you must not get
wrong. Where they differ, CLAUDE.md is more detailed, never more permissive.

This project's value is that every date and figure can be traced to the lab's
own words. A plausible record with an invented source is worse than no record:
it is the one failure the project exists to prevent, and the build cannot
always catch it. When in doubt, leave the field `null` and say why in the PR.

## The job: "update LLM World"

1. **Find leads.** Start from the newest open GitHub issue labelled
   `candidates` (opened daily by `candidates.yml`). Then run
   `npm run candidates -- --days=7 --all`, and web-search each lab listed at
   the end under "not covered" and "no channel here watches", one search per
   lab. Trackers and news are leads only, never sources.
2. **Verify each lead on the lab's own page** — announcement, docs, changelog,
   model card or repo. Take the date the lab states. A Hugging Face repo's
   creation date is NOT a release date. If you cannot open the lab's page
   (openai.com, x.ai, ai.meta.com and qwen.ai refuse plain HTTP — use a
   browser), list the lead as unverified in the PR and do not add it.
3. **Decide what it is** (docs/TAXONOMY.md):
   - a separately named model → a model record;
   - a speed or price tier of an existing model, a feature, or a model newly
     offered on another company's platform → nothing (or an `events[]` entry
     on the existing record, e.g. `api_availability`);
   - an agent product (Grok Bot, OpenAI dots) or a harness → an `agent` or
     `harness` milestone in `data/milestones.json`;
   - a decision model → `primary_type: decision` ONLY if the lab's page
     evidences all four parts of TAXONOMY §6a;
   - one person's fine-tune with no lab behind it → nothing;
   - a type the schema does not have (robot control, time-series
     forecasting) → nothing; raise it in the PR.
4. **Add it with the tools** (below), then `npm run enrich` if you have time,
   then `npm run check`.
5. **Review your own diff** with `node scripts/diff-records.mjs origin/main`
   and open a pull request (below).

## Hard rules — each one was broken by an agent at least once

1. **Never write `data/*.json` by hand or with another language's JSON
   library.** Use `node scripts/add-model.mjs spec.json --write` for new
   records, `node scripts/apply-specs.mjs` for researched values, and the
   enrichment scripts for everything else. For anything they cannot do (an
   `events[]` entry), write a small Node script that saves through
   `saveDataset()` in `lib/dataset.mjs`. Python's `json.dump` re-encodes the
   file; one such commit changed 658 lines to add 2 records. *The validator
   now fails any file not in canonical form.*
2. **Never write an `archived_url`.** Leave it `null`;
   `node scripts/archive-sources.mjs --save --write` finds or requests the
   real snapshot. A timestamp like `20261012000000` is a placeholder that
   claims a capture nobody checked. *The validator now rejects it.*
3. **Never hand-set `modalities`, `capabilities`, `tags`, `evidence`, or
   `provenance.status` / `confidence` on a new record.** `add-model.mjs`
   starts every record as `partially_verified`; the enrichment scripts read
   the archived sources and record what they say; `reconcile-status.mjs`
   decides the status. Writing "text in, text out" for a multimodal model, or
   `verified` with confidence 90, is a claim nobody checked.
4. **Never change a status by hand, in either direction.** A source that was
   unreadable today is not evidence of anything; rerun the tool later.
5. **No third-party figures.** No benchmark scores, indices (Artificial
   Analysis etc.), prices or dates from news, trackers or aggregators — not in
   fields, not in `note`. A secondary source may be cited as context but can
   never back a value. Lab-reported benchmarks go through
   `extract-benchmarks.mjs`, which records them as `vendor_reported`.
6. **Never estimate.** An undisclosed figure is `null`.
7. **Do not commit what you have not read.** After any enrichment run, read
   `diff-records.mjs` output. Spot-check every field that changed on more
   than a handful of records, and every provenance status that moved.
   Enrichment tools have had bugs (a pricing extractor once gave every GPT-6
   record the first price on a shared changelog page); you are the reviewer.
8. **Never push to `main`. Never force-push.** Work on a branch named
   `agent/<agent-name>/<yyyy-mm-dd>`, push it, and open a pull request. The
   pre-push hook runs `npm run check`; do not bypass it (`--no-verify` is
   forbidden). Run `npm run setup` once per clone so the hook is active.
9. **Do not commit generated output** (anything under "Generated by
   scripts/build.mjs" in `.gitignore`) or files outside the task.

## The pull request

Title: `Update LLM World — <date>`. Body, in this order:

- **Added** — one line per record: name, lab, date, and the URL the date
  comes from.
- **Not added, and why** — every lead you rejected: serving tier, product,
  no lab source, page unreadable, type not in schema.
- **Unverified leads** — what a person (or a browser-capable agent) still
  needs to check.
- **Dataset diff** — paste `node scripts/diff-records.mjs origin/main`.
- **Checks** — confirm `npm run check` passed.

Tick the matching items in the `candidates` issue and link the PR there.

## Stop and ask instead of guessing

- A lab not in the dataset (adding one also needs a logo, a slug and colour
  tokens — see CLAUDE.md).
- A model type the schema does not have.
- Two primary sources that disagree on a date.
- Any change to scripts, workflows, the schema or the validator. Data PRs and
  code PRs are separate, so each can be reviewed for what it is.

## Commands

```bash
npm run setup                               # once per clone: enables the pre-push gate
npm run candidates -- --days=7 --all        # leads from changelogs and feeds
npm run sweep                               # changelogs only, with blind spots listed
npm run feeds                               # newsroom RSS only
node scripts/add-model.mjs spec.json        # dry run; add --write to apply
npm run enrich                              # archive, trace, detect — slow, network
node scripts/reconcile-status.mjs --write   # status from evidence
node scripts/update-readme.mjs --write      # README statistics
node scripts/diff-records.mjs origin/main   # what your branch did, by record
npm run check                               # validate → build → smoke
```
